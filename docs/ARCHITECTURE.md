# Architecture

A website **with no server**. The heavy work is done once on a PC (Python
pipeline) and produces small files; the website downloads them and computes
each mission **in the user's browser**. It can be published for free on
GitHub Pages.

```
                 ONCE, ON A PC                                   IN THE BROWSER
 ┌──────────────────────────────────────────┐        ┌──────────────────────────────────────┐
 │ NASA PDS (LOLA)      NASA/JPL NAIF (SPICE)│        │  User: dates, duration, weights       │
 │   relief, slope,       DE440 ephemerides  │        │                  │                    │
 │   permanent shadow,    Moon orientation   │        │  workers (1 per core)                 │
 │   mean illumination                       │        │   Sun and Earth vs horizon, hour by   │
 │          │                 │              │        │   hour, for the 160,000 pixels        │
 │          ▼                 ▼              │        │                  │                    │
 │   pipeline/moonsite (Python, numpy)       │ ─────► │  score + hotspots                     │
 │   1 km grid · horizons · validation       │ ~13 MB │                  │                    │
 │          │                                │        │  heat map + list of sites             │
 │          ▼                                │        │  (Lunar Horizon design system)        │
 │   web/public/data/*                       │        └──────────────────────────────────────┘
 └──────────────────────────────────────────┘
```

## Folders

| Folder | What it holds |
|---|---|
| `pipeline/moonsite/` | Python pipeline. `config.py` gathers every assumption (sources, grid, dates). |
| `web/` | Static website: Vite + React 18 (required by the design system). |
| `web/public/data/` | Data generated by the pipeline. Committed to git so the site can be published without recomputing. |
| `web/public/design-system/` | Shared "Lunar Horizon" design system (see `SOURCE.md`). Not edited by hand. |
| `web/src/engine/` | Computation: geometry, workers, score, hotspots. No React. |
| `web/src/components/` | Interface: map, mission panels, priorities, sites, Learn. |
| `tools/` | `sync_design_system.py`: pulls in changes from the shared design system. |
| `.cache/` | NASA downloads (~330 MB). Outside git. |

## Grid

- South polar stereographic, the same as LOLA. **Pixels of 1 km × 1 km**, 400 × 400
  (about 160,000), from −200 to +200 km around the pole: it reaches ~83.5°S and covers
  all the published Artemis III candidate regions.
- Each pixel draws on finer data: horizon traced over the 240 m relief,
  slope = median of 16 samples of 240 m, shadow = % of the km in shadow (120 m).
- To change the resolution: `GRID_PX_M` and `GRID_HALF_M` in `config.py`, then run
  the pipeline again.

## Files generated by the pipeline (`web/public/data/`)

| File | Content | Size |
|---|---|---|
| `manifest.json` | Grid, layers, units, sources, metadata | 5 KB |
| `layers/*.f32` | Fixed layers, Float32, row 0 at the top | 640 KB each |
| `horizon.u8` | Horizon per pixel, 72 directions, 1 byte (0.1°) | 11.5 MB |
| `ephem.f32` | Sun and Earth (km, MOON_ME), every hour 2026–2030 | 1 MB |
| `hillshade.png` | Shaded relief (visual aid, it is not light) | 1.4 MB |
| `validation.json` | Results against Horizons and LOLA | 2 KB |

## Computing a mission (in the browser)

1. The user gives the **landing window** (max. 60 days) and the **time on the surface**.
2. For each pixel and each hour: elevation and azimuth of the Sun and of the Earth in the
   local frame, compared with the terrain horizon at that azimuth.
   - Sun: fraction of the disc visible (true angular radius).
   - Earth: centre above the horizon. Parallax is included.
3. Every landing time is tried (every 3 h) and the best one per pixel is kept
   according to the Sun and Earth weights. The longest continuous night is computed.
4. **Score** (0–100) = 100 · Σ weight × factor / Σ weight, with factors Sun, Earth,
   gentle terrain and closeness to permanent shadow. The **filters** (maximum slope,
   permanent shadow, battery autonomy) remove pixels.
5. **Hotspots**: connected groups of the 3 % of pixels with the best score,
   ordered by their best pixel.

Changing the terrain or ice weights, or the filters, applies at once. Changing the Sun
or Earth weights launches the computation again, because the best landing time changes.

## Scientific conventions (do not change without notice)

- `MOON_ME` frame (the one LOLA uses). Planetocentric latitude, longitude positive to the east.
- Apparent directions `LT+S` (like Horizons "airless apparent"). No refraction: the
  Moon has no atmosphere.
- Dates in UTC. Observer 2 m above the terrain.
- Plane: `x = rho·sin(lon)`, `y = rho·cos(lon)`; row 0 at the top (+y, longitude 0°).
- Azimuth clockwise from north (north = towards the north pole = away from the south pole).

The same formulas are in `pipeline/moonsite/visibility.py` (Python, for validation) and
in `web/src/engine/` (JavaScript, for the website).

## Known limits

- 1 km and 5° of azimuth: good for comparing regions, not for certifying a site.
- Relief closer than 300 m is not resolved; rocks and small craters are not in the data.
- Energy is an estimate (fraction of the solar disc), not an electrical model.
- A visible Earth does not guarantee a link (there is no link budget).
- "Ice" = distance to permanent shadow, not measured ice.
